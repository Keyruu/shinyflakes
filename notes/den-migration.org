Migrate shinyflakes from blueprint → den (aspect-oriented).

Three primitives:
- Entities: ~den.hosts~ / ~den.hosts.<sys>.<host>.users.<user>~
- Aspects: ~den.aspects.<name> = { nixos = ...; homeManager = ...; includes = [...]; }~
- Pipes: ~den.quirks.<name>~ + ~pipe.from/collect/expose/transform~

Key insight: ~nixos~ / ~homeManager~ blocks are *literal NixOS modules*. Every existing
~services.X.enable = true~ carries over byte-for-byte. Only structure changes.

** Dashboard generation                                              :pipes:
:PROPERTIES:
:CUSTOM_ID: dashboard
:END:

Today: ~flake.allMyServices~ walk on prime, every service declares
~services.my.X.dashboard~, tightly coupled.

Tomorrow: ~den.quirks.dashboard~. Each stack emits freely. Prime consumes
~pipe.collect~ across all hosts. Zero coupling.

#+BEGIN_SRC nix
# Register quirk
den.quirks.dashboard = { description = "Service dashboard entries"; };

# Producer (in any stack module)
den.aspects.immich = {
  dashboard = {
    enable = true; title = "Immich";
    icon = "https://cdn.jsdelivr.net/gh/homarr-labs/dashboard-icons/svg/immich.svg";
    url = "https://photos.peeraten.net";
    groups = [ "family" ];
  };
  nixos = { ... };  # existing service config unchanged
};

# Consumer + policy
den.policies.fleet-dashboard = { host, ... }:
  let inherit (den.lib.policy) pipe; in
  [ (pipe.from "dashboard" [
      (pipe.collect ({ host, ... }: true))
      (pipe.filter (e: e.enable or false))
    ])
  ];
den.schema.host.includes = [ den.policies.fleet-dashboard ];

den.aspects.prime-dashboard = {
  nixos = { dashboard, ... }: {
    services.caddy.virtualHosts."dash.peeraten.net" = {
      root * ${perSystem.self.dashboard.override { apps = dashboard; }};
      # ... rest of Caddy config ...
    };
  };
};
#+END_SRC

Same trick kills ~flake.lib.allMyServices~-based walks everywhere — including Gatus endpoints.

** Proxying prime → mentat                                         :proxy:pipes:
:PROPERTIES:
:CUSTOM_ID: proxy
:END:

Today: ~nix/hosts/prime/modules/proxy.nix~ has hardcoded
~services.mesh.people.lucas.devices.mentat.ip~ lookups + big ~proxyHosts~ attrset.

Tomorrow: ~den.quirks.proxy~. Each stack emits its proxy target. Prime resolves
~target~ → mesh IP.

#+BEGIN_SRC nix
den.quirks.proxy = { description = "Reverse proxy targets"; };

den.aspects.immich = {
  proxy = {
    domain = "photos.peeraten.net";
    port = 2283;
    cloudflare = true;
    target = "mentat";  # logical name, not IP
    authGroup = "family";
  };
  nixos = { ... };
};

den.policies.resolve-proxy-target = { host, ... }:
  let inherit (den.lib.policy) pipe; in
  [ (pipe.from "proxy" [
      (pipe.transform (p: p // {
        targetIp = den.hosts.x86_64-linux.${p.target}.meshIp;
      }))
    ])
  ];

den.aspects.prime-proxy = {
  nixos = { proxy, ... }:
  let byDomain = lib.groupBy (p: p.domain) proxy;
  in {
    services.caddy.virtualHosts = lib.mapAttrs (domain: ps:
      let cfg = lib.head ps; in {
        extraConfig = ''
          reverse_proxy ${cfg.targetIp}:${toString cfg.port}
          ${lib.optionalString cfg.cloudflare "import cloudflare-only"}
          ${lib.optionalString (cfg.authGroup != null) ''
            forward_auth 127.0.0.1:8010 {
              uri /api/authz/forward-auth
              copy_headers Remote-User Remote-Groups Remote-Name Remote-Email
            }
          ''}
        '';
      }) byDomain;
  };
};
#+END_SRC

Adding a reverse-proxied service = add ~proxy = { ... };~ to its stack. Done.

** Mesh devices + dynamic ACLs                                  :mesh:devices:
:PROPERTIES:
:CUSTOM_ID: mesh-devices
:END:

Today: ~nix/hosts/mentat/modules/mesh.nix~ hardcodes device list. New device = edit
file + commit.

Tomorrow: new entity kind ~den.devices.~ with freeform attrs. nftables ACLs
generated from the entity list.

#+BEGIN_SRC nix
den.devices.x86_64-linux.mentat.laptop = {
  owner = "lucas";
  ip = "100.67.0.42";
  publicKey = "...";
  canAccess = [ "homelab" "family" ];
};

den.aspects.mesh-firewall = {
  nixos = { devices, ... }:
    let rules = lib.concatMapStrings (d:
      lib.concatMapStrings (net: ''
        ip saddr ${d.ip} ip daddr ${net} accept comment "${d.name}"
      '') d.canAccess
    ) devices;
    in {
      networking.nftables.tables.wireguard-forward.content = ''
        chain forward {
          type filter hook forward priority filter; policy accept;
          ${rules}
        }
      '';
    };
};
#+END_SRC

** Mentat port — patterns & gotchas                               :conventions:
:PROPERTIES:
:CUSTOM_ID: mentat-port-patterns
:END:

Patterns learned porting ~nix/hosts/mentat/~ to den. Apply to the rest
of the hosts. Most of these are den mechanics, not mentat-specific.

*** Argument scoping

**** Outer module function (~{ ... }:~) — only what *must* be there

Use bare ~{ ... }:~ unless one of these is genuinely required at the
outer scope:

- ~inputs~ — for module imports inside a SET body (e.g. ~den.aspects.<x>.nixos = { imports = [ inputs.disko.nixosModules.disko ]; ... }~). Nix module imports must be a list literal at merge time, so they can't live in a lazy inner-function body.
- ~den~ — if the outer set references ~den.aspects.<x>~ / ~den.batteries.X~ / ~den.lib.X~ directly.
- ~config~ — rare; only if you need to read merged config at outer-scope evaluation time. Almost never needed.

Don't add ~pkgs~, ~lib~, ~self'~, ~inputs'~ to the outer. They have
no use up there and the den framework doesn't auto-forward them.

**** Inner nixos function (~nixos = { ... }:~) — prefer inner args

Declare what you actually reference. Common set:
~{ config, pkgs, lib, ... }:~. Add ~inputs~ if you read it (some
services do, e.g. copyparty imports ~inputs.copyparty.nixosModules.default~
inside the inner function).

~self'.packages.X~ is auto-provided by ~den.batteries.self'~. Don't
try ~perSystem.self.X~ — that doesn't exist.

~inputs.X~ (raw, no prime) for the *flake* input set is NOT a module
arg. The den convention is ~inputs'.X~ (with prime) provided by
~den.batteries.inputs'~.

**** Reaching outer-scope vars inside the inner function

The inner function doesn't see the outer function's let-bindings via
Nix's lexical scope the way you'd expect — because den calls them
through ~_module.args~, not via direct call. Workarounds:

- For ~config~: bind in the outer ~let~ and reference via the bound name inside:
  #+BEGIN_SRC nix
  { ... }:
  let
    topLevelConfig = config;
  in
  {
    den.aspects.server.mesh-firewall = {
      nixos = { config, lib, ... }: {
        # ... topLevelConfig.den.people ...
      };
    };
  }
  #+END_SRC
- For ~den~: same pattern (~let den' = den; in ...~) if needed.
- For everything else: just pass as an inner arg.

*** Per-user aspect = single source of truth for ~den.aspects.core~

~modules/users/<name>.nix~ already includes ~den.aspects.core~ (the
aggregator). Host ~default.nix~ files must NOT also list the
individual ~den.aspects.core.{common,secrets,nixConfig,...}~ —
otherwise den applies them at both host and user scopes and
duplicate definitions explode (~boot.kernelPackages~,
~boot.kernel.sysctl~, etc.).

*** define-user battery clashes with ~root~ (uid 0)

~den.batteries.define-user~ sets ~users.users.<name>.{isNormalUser = true, home = "/home/<name>"}~. For root (uid 0) this is wrong. Override
in the host aspect with ~lib.mkForce~:

#+BEGIN_SRC nix
users.users.root = {
  isSystemUser = lib.mkForce true;
  isNormalUser = lib.mkForce false;
  home = lib.mkForce "/root";
};
#+END_SRC

*** ~services.my.<x>~ schema quirks

- ~dashboard.description~ does NOT exist. Use top-level ~description~ (shown on docs) + ~dashboard.title~ (card title).
- ~services.my.<x>.dashboard.enable~ requires ~domain~. Set ~dashboard = { enable = false; };~ for internal-only services (hermes, hytale, isponsorblocktv, karaoke, matter, mqtt, openthread, recyclarr, terraria).
- ~services.my.<x>.monitor.enable~ requires ~domain~ or ~monitor.url~. Set ~monitor = { enable = false; };~ on the same internal-only services.
- ~proxy.whitelist.people = [ "lucas" ]~ is the legacy blueprint field. The den ~nginx-whitelist~ aspect reads ~whitelist.enable~ and derives IPs from ~den.people.<name>.service-access~. Replace with ~whitelist.enable = true;~ on the affected service.

*** Stacks: drop the blueprint quadlet helpers

Don't carry over from the blueprint:
- ~let my = config.services.my.<x>; in { ... }~ — fine, but ~my.port~ / ~my.stack.path~ resolve through the standard NixOS option system; just reference them inline.
- ~inherit (config.virtualisation.quadlet) containers;~ and ~inherit (flake.lib) quadlet;~ — gone. The stack module auto-wires everything.
- Container-name prefixing: single-container stacks keep the short name; multi-container stacks get ~<stack>-<short>~. Stack module handles this.
- ~dependsOn = [ "sibling" ]~ uses short sibling names; stack module generates After/Requires with prefixed refs. Don't write ~containers.<x>.ref~ manually.
- Hardcoded ~virtualisation.quadlet.containers.X.containerConfig.publishPorts~ overrides (e.g. media services adding ports to gluetun's container) stay inline — they're not stack-managed.

*** Misc gotchas

- ~security.acme.acceptTerms = true~ must be set somewhere. The den ~server.nginx~ aspect sets it. Include ~den.aspects.server.nginx~ on any host that uses ACME (mentat does for ~*.lab.keyruu.de~, ~*.port.peeraten.net~, traccar.peeraten.net, owntracks.peeraten.net).
- The ~services.mesh~ option bridge: ~modules/aspects/options/mesh.nix~ declares the legacy ~interface/ip/subnet/client/server~ options used by ~mesh-firewall~, ~mesh-server~, ~workstation.mesh-client~, and many service aspects that reference ~config.services.mesh.ip~ (blocky, jellyfin, seerr, karaoke, traccar, radicale, etc.). Keep it in ~den.default.includes~ until the last consumer migrates to read ~den.hosts.X.mesh.ip~ / ~den.people.X.devices.<dev>.ip~ directly.
- ~flake.lib.quadlet.alias containers.X~ — gone in den. Reference inter-container hostnames as ~<stackName>-<shortName>~ (e.g. ~karakeep-meilisearch~, ~paperless-broker~). Stack module sets ~networkAliases~ and the bridge network.
- ~perSystem.copyparty.default~ (and similar) doesn't exist. Reference upstream packages directly: ~inputs.copyparty.packages.${pkgs.stdenv.hostPlatform.system}.default~.
- Module function arg ~inputs~ is the raw flake input set; ~inputs'~ (prime) is the per-system variant provided by den. Use ~inputs'~ inside nixos functions, ~inputs~ only for outer-scope module imports.

*** Migration workflow that works

1. Create ~modules/aspects/services/<svc>.nix~ (or ~server/<x>.nix~) by byte-for-byte copy of the blueprint file, wrapping in ~{ ... }: { den.aspects.services.<svc> = { nixos = { config, pkgs, lib, ... }: { ... }; }; }~.
2. Drop ~let my = config.services.my.<x>; in { ... }~ if you're not sure — just inline the values. Re-add when you need cross-references.
3. Strip blueprint-specific helpers: ~flake.lib~, ~quadlet~, ~perSystem~.
4. Add inner args as needed (~pkgs~ for ~with pkgs;~ or ~writeShellApplication~, ~lib~ for ~lib.mkForce/lib.mkIf/lib.mkDefault~, ~config~ for ~config.services.X~ references).
5. Fix schema mismatches (~dashboard.description~ → top-level ~description~, add ~dashboard.enable = false;~ for internal services).
6. Wire into ~modules/hosts/<host>/default.nix~ via ~includes~. Don't re-include per-user aspects (core, batteries).
7. ~nixos-rebuild dry-build --flake '.?submodules=1#<host>'~. Add git-tracked files before eval (import-tree reads committed state).
